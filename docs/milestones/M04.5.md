# M04.5 — Operación continua y orquestación autónoma

## Estado

**COMPLETADO; VALIDACIÓN OFFLINE Y LIVE INTEGRAL SUPERADAS (2026-10-31).**

El supervisor condujo el escenario Issue → plan → dos tareas dependientes → PRs →
merges, respetando pausas y gates de lectura, inferencia y publicación. Se comprobó
`dry-run`, `once`, apagado SIGTERM seguro, persistencia, deduplicación y continuación
tras reinicio. Evidencias en [M04-live-results.md](M04-live-results.md).

## Alcance y arquitectura

`vibecoder.supervisor` incorpora en un solo proceso:

- `Scheduler`: deriva intenciones desde bootstrap, Issues, planes, tareas, PRs y
  correcciones persistidos.
- `SupervisorStore`: trabajos, unicidad, leases, pausas, errores y actividad.
- `WorkflowDispatcher`: llama exclusivamente a `BootstrapService`,
  `IssueCoordinationService`, `TaskExecutionService` y
  `PullRequestReviewService`.
- `Supervisor`: ciclo `once`/`run`, timeout, recuperación y apagado por SIGINT/SIGTERM.

El job no duplica el workflow ni concede autorización. Los servicios de origen vuelven
a validar proyecto, aprobación, agente, cuenta, dependencias, workspace, SHA y remoto.

## Persistencia y planificación

La migración 0012 crea `supervisor_jobs`, `supervisor_controls` y
`supervisor_activity`. La clave lógica `(tipo, origen)` solo admite una intención
activa. Se priorizan recuperación, materialización y trabajo local antes del polling
periódico. `BLOCKED` y `UNKNOWN` no se seleccionan como trabajos ordinarios.

Los trabajos se clasifican como lectura remota, inferencia Codex, escritura local,
escritura remota o recuperación. La configuración permite límites globales, por
proyecto, agente y cuenta, además de exclusión por workspace/PR y límite GitHub.
El valor predeterminado es una ejecución global.

## Reservas, errores y recuperación

El claim persiste runner, token, adquisición, heartbeat y expiración. Una reserva
expirada queda `UNKNOWN` con acción `reconciliar`; nunca vuelve a `PENDING` por sí sola.
Los errores transitorios y rate limits usan backoff exponencial acotado y respetan
`retry_after` cuando el adaptador lo proporciona. Autenticación, autorización,
configuración y validación bloquean. Timeout o causa desconocida conservan resultado
indeterminado.

Las pausas globales o por proyecto distinguen toda operación, inferencia y publicación.
El apagado deja de seleccionar trabajo; no declara completada ninguna operación por
cerrar el proceso.

## Configuración

Ejemplo no sensible `supervisor.json`:

```json
{
  "database": "/ruta/state.sqlite3",
  "accounts": "/ruta/accounts.json",
  "task_workspace_root": "/ruta/workspaces/tasks",
  "authorized_users": ["usuario-github"],
  "publication_enabled": false,
  "projects": {
    "UUID_PROYECTO": {
      "workspace": "/ruta/checkout-limpio",
      "allowed_paths": ["src", "tests", "doc", "README.md"]
    }
  }
}
```

El token continúa exclusivamente en `VIBECODER_GITHUB_TOKEN`; el archivo no contiene
secretos. `publication_enabled` comienza a `false` para evitar escrituras accidentales.

## CLI

```bash
.venv/bin/python -m vibecoder.supervisor --config supervisor.json config-check
.venv/bin/python -m vibecoder.supervisor --config supervisor.json dry-run
.venv/bin/python -m vibecoder.supervisor --config supervisor.json status
.venv/bin/python -m vibecoder.supervisor --config supervisor.json jobs
.venv/bin/python -m vibecoder.supervisor --config supervisor.json once
.venv/bin/python -m vibecoder.supervisor --config supervisor.json run
.venv/bin/python -m vibecoder.supervisor --config supervisor.json pause --inference --actor operador
.venv/bin/python -m vibecoder.supervisor --config supervisor.json resume --actor operador
.venv/bin/python -m vibecoder.supervisor --config supervisor.json reconcile
```

`dry-run` no escribe SQLite, no crea directorios, no llama GitHub ni Codex. `once` y
`run` sí pueden producir los efectos autorizados; las publicaciones además necesitan
el gate de configuración.

## Observabilidad y seguridad

La actividad persistida incluye operación, proyecto, estado, duración y categoría de
error. No guarda tokens ni contenidos de sesión. La salida de estado muestra conteos,
jobs y pausas. Se mantienen todas las protecciones previas: sin force push, merge,
cierre automático, ejecución de tests no autorizados ni exposición del token a Codex.

## Pruebas y aceptación

Las pruebas offline cubren deduplicación, prioridad, límites, leases, heartbeat,
expiración conservadora, pausa persistente, backoff, timeout `UNKNOWN`, ciclo único,
loop, apagado y dry-run sin efectos. La suite completa M00–M04.5 se ejecuta sin red ni
inferencia. El procedimiento y los resultados de la validación integral live están en
[M04-live-validation.md](M04-live-validation.md) y
[M04-live-results.md](M04-live-results.md).

## Limitaciones

- Un solo proceso activo por SQLite; no hay locks distribuidos.
- Dispatcher secuencial aunque el modelo ya impone límites multidimensionales.
- Polling, sin webhooks.
- Observabilidad local, sin Prometheus/Grafana.
- Los estados `UNKNOWN` necesitan reconciliación explícita.
- No hay merge ni cierre automático de Issues.
