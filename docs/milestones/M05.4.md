## Arquitectura y formato

`MaintenanceService` es independiente de argparse y reutilizable por futuras
interfaces. El formato de backup 1 es un directorio `0700` con manifiesto JSON y
payload validado. Incluye configuración, SQLite, secretos, cuentas Codex, workspaces y
estado; excluye runtime efímero y logs.

La quiescencia exige servicio detenido declarado, pausa global y ausencia de jobs,
leases o ejecuciones activas. SQLite se captura con su API oficial. Cada archivo tiene
checksum, tamaño y modo; se rechazan traversal, symlinks y hardlinks.

## Restauración y barrera

La restauración verifica, crea backup previo, usa staging y journal, y valida el
resultado. Un fallo se detecta en el siguiente intento y solo admite rollback
conservador. Toda restauración termina `CONFIGURED` y pausada porque GitHub/Codex no se
restauran junto al filesystem.

## Upgrade

La versión 0.4.0 añade la migración 0015 y backup pre-migración en `postinst` durante
upgrades reales. El runtime rechaza esquemas futuros. No existe downgrade automático.

## Seguridad y limitaciones

Los backups contienen secretos y no se cifran en M05.4. Se almacenan localmente con
permisos restrictivos y nunca se publican. La atomicidad multiarchivo se resuelve con
journal y backup previo, no se promete como transacción única. Systemd real y Ubuntu
siguen pendientes de M05.5.
