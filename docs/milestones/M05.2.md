# M05.2 — Administración CLI y configuración segura

## Estado

**COMPLETADO; VALIDACIÓN OFFLINE Y DE PAQUETE AISLADO SUPERADAS EN DEBIAN FORKY.**

## Arquitectura

`vibecoder-admin` usa `AdministrationService`; no contiene reglas exclusivas del
parser. Reutiliza `OrchestratorCore`, `AgentManagementService`, `SupervisorStore` y las
migraciones SQLite. SQLite conserva identidades/metadatos; los JSON, configuración
runtime; el almacén protegido, valores sensibles.

La migración 0013 añade metadatos de credenciales y auditoría sin alterar tablas
históricas. Las configuraciones M05.1 siguen siendo válidas. El supervisor admite un
secreto GitHub por referencia, con fallback de entorno para instalaciones anteriores.

## Ciclo y seguridad

Las mutaciones requieren root. `NOT_CONFIGURED` permite preparar recursos;
`CONFIGURED` indica configuración estructural; `READY` requiere un proyecto habilitado
y cuentas localmente válidas. Cambiar configuración crítica degrada el estado.
Habilitar un proyecto no aprueba planes ni activa workflows por sí mismo.

Inferencia y publicación por proyecto quedan deshabilitadas al registrarlo. Las pausas
reutilizan controles del supervisor. Los secretos se introducen por TTY sin eco o
descriptor, nunca por argumentos.

## Pruebas, limitaciones y aceptación

Las pruebas cubren autorización, persistencia, idempotencia, aislamiento de
`CODEX_HOME`, configuración atómica, ciclo operativo, secretos, traversal/symlinks,
diagnóstico sin efectos y regresión. No usan GitHub ni Codex reales.

Quedan fuera debconf, administración multiusuario, web/API, revocación remota, backup
y validación real de systemd/Ubuntu. M05.3 podrá crear la autoridad inicial sin cambiar
los servicios administrativos.
