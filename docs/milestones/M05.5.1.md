# M05.5.1 — Consolidación del soporte Debian

## Estado

**COMPLETADO Y VALIDADO LIVE (2026-11-09).** La VM `192.168.56.6` se convirtió
de Debian 13.7 trixie a Debian unstable usando exclusivamente repositorios oficiales
firmados. Tras el reboot ejecutó `forky/sid`, kernel `7.3.3+deb14-amd64`, systemd
262 como PID 1, Python 3.14.10 y APT sin paquetes pendientes ni incidencias de dpkg.
SSH conservó la identidad previamente verificada y volvió a estar operativo.

## Evidencia de producto

- El paquete 0.4.0 se construyó con debhelper/pybuild dentro de sid; 293 pruebas
  pasaron y 45 integraciones live opt-in fueron omitidas. Lintian no emitió tags.
- Instalación limpia por APT, debconf, esquema SQLite 15, permisos, usuario de
  servicio, autostart e instalación inerte `NOT_CONFIGURED`: superados.
- Configuración ficticia, diagnóstico 10/10, activación READY explícita con
  inferencia y publicación deshabilitadas: superados.
- Restart, SIGTERM, reboot, journald, rechazo administrativo a usuario no
  privilegiado y hardening systemd 4.3/OK: superados.
- Backup offline consistente, verificación, restore, propietarios, degradación a
  CONFIGURED, barrera y rollback de restore interrumpido: superados.
- Remove/reinstall conservó datos; purge mantuvo datos no vacíos conforme a la
  política conservadora.
- El artefacto histórico auténtico 0.3.0 (`14141a4f…1af3`) fue instalable con
  dependencias oficiales de sid. El upgrade a 0.4.0 creó backup previo, migró
  esquema 14→15 y conservó secreto ficticio y workspace Git modificado.

No se utilizó GitHub ni Codex, no se instaló nada en el host y no se modificó la VM
Ubuntu.

## Decisiones

- Debian 13 trixie es la plataforma soportada.
- Debian sid es validación continua: este resultado cubre el snapshot observado,
  no todas las futuras mutaciones de unstable.
- Ubuntu 24.04 es experimental; 26.04 queda para evaluación futura.
- Se conserva la pequeña capa Pydantic 1/2: está probada en Pydantic 1.10 y 2.14,
  no cambia el dominio y evita una regresión innecesaria en entornos experimentales.
- No se promete downgrade automático. El runtime histórico 0.3 no puede adquirir
  retroactivamente el rechazo de esquema 15; volver exige restaurar primero un
  backup compatible y mantener la barrera hasta verificarlo.

Los resultados consolidados están en [M05-final-results](M05-final-results.md).
